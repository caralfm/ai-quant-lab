## 1. 海龟交易法则 策略定义

### 1.1 策略背景

海龟交易法则是由 Richard Dennis 和 William Eckhardt 在 1980 年代开发的经典趋势跟踪策略。其核心思想：**趋势跟踪 + 波动率仓位管理 + 严格止损**。

本看板同时实现原版的两套系统：

| 系统 | 入场周期 | 出场周期 | 适用场景 |
|------|---------|---------|---------|
| System 1 (S1) | 20 日通道突破 | 10 日通道突破 | 短期趋势，更敏感 |
| System 2 (S2) | 55 日通道突破 | 20 日通道突破 | 长期趋势，更稳健 |

默认同时展示 S1 和 S2 的回测结果，用户可以单独勾选启用/禁用。

### 1.2 入场规则 (Entry)

**做多入场（本看板首版仅做多，A 股融券限制暂不做空）:**

```
S1_Entry: 当前收盘价 close > 过去 EntryPeriod 个交易日的最高价 (不含当日)
S2_Entry: 当前收盘价 close > 过去 EntryPeriod 个交易日的最高价 (不含当日)
```

**过滤器 (仅 S1 启用):**
- 如果上一次 S1 信号是**盈利出场**，则跳过本次 S1 入场信号。
- 盈利出场定义: 退出价 > 入场均价。
- 参数 `S1_LastTradeFilter: true | false` 可关闭此过滤器。

### 1.3 加仓规则 (Pyramiding)

入场后，价格每向有利方向移动 `AddUnitATR` 倍 ATR，加仓 1 个单位。

```
加仓条件: close >= 最近一次入场价 + AddUnitATR × ATR(20)
最大持仓单位: MaxUnits (默认 4)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| AddUnitATR | 0.5 | 加仓间距 (ATR 倍数) |
| MaxUnits | 4 | 同一标的同一方向最大加仓次数 |

**关键实现细节:**
- 第一个单位入场后，加仓价位 = 上一单位入场价 + AddUnitATR × ATR(入场日)
- 加仓可以发生在同一天（如跳空高开满足多个加仓价位）
- 每个加仓单位独立计算止损

### 1.4 止损规则 (Stop Loss)

每个持仓单位独立止损，基于该单位的实际入场价：

```
止损价 = 该单位入场价 - StopATR × ATR(入场日)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| StopATR | 2.0 | 止损距离 (ATR 倍数) |

- 盘中触及即止损（用当日最低价 low 判断）
- 开盘跳空越过止损价 → 以开盘价 open 止损

### 1.5 出场规则 (Exit)

```
S1_Exit: 当前收盘价 close < 过去 ExitPeriod 个交易日的最低价 (不含当日)
S2_Exit: 当前收盘价 close < 过去 ExitPeriod 个交易日的最低价 (不含当日)
```

- 出场信号对所有持仓单位统一执行（全部平仓）
- 止损优先于通道出场（先判断止损，再判断通道出场）

## 2. 指标计算依赖

回测需要的中间指标计算沿用 task02 `indicator_lab_spec.md` 的公式：

| 指标 | 用途 | 公式来源 |
|------|------|---------|
| ATR(20) | 仓位管理、止损距离、加仓间距 | Wilder smoothing, indicator_lab_spec §2.4 |
| N 日最高价 (Donchian High) | 入场信号 | `max(high[t-N : t-1])` (不含当日) |
| N 日最低价 (Donchian Low) | 出场信号 | `min(low[t-N : t-1])` (不含当日) |

**计算顺序保证:**
1. 先算 ATR(20) → 至少需要 21 个交易日数据（warmup）
2. 再算 Donchian High/Low → 最多需要 55 个交易日数据（warmup）
3. 回测从第 56 个交易日开始（保证所有指标有效）

> 决策: 预热期内不产生信号，预热期长度 = max(EntryPeriod_S2, ATR_Period) + 1 = 56 日。比 task02 D4 的"保留 NaN"更严格——回测场景必须在数据有效后才开始。

## 3. 回测核心流程

### 3.1 逐日遍历伪代码

```
输入: OHLCV 日线数据 (已按日期升序排列)
输出: trades[], equity_curve[], metrics{}

初始化:
  position = 0                    # 当前持仓单位数
  units = []                      # [{entry_price, entry_date, stop_price}]
  last_trade_was_winner = true    # S1 过滤器状态
  cash = initial_capital
  equity_curve = []

for each trading day t in [warmup_end : last_day]:
    # ---- 有持仓时的检查 ----
    if position > 0:
        for each unit in units:
            if low[t] <= unit.stop_price:
                # 止损出场
                exit_price = open[t] if open[t] < unit.stop_price else unit.stop_price
                记录 trade: entry_date=unit.date, exit_date=t, entry_price=unit.price,
                           exit_price, pnl, exit_reason="止损"
                移除该 unit; position -= 1

    # ---- 出场信号 (通道突破) ----
    if position > 0 and close[t] < DonchianLow_ExitPeriod[t]:
        执行全部平仓
        for each unit in units:
            记录 trade with exit_reason="通道出场"
        清空 units; position = 0
        last_trade_was_winner = (平仓价 > 加权均价)   # 用于 S1 过滤

    # ---- 入场信号 (通道突破) ----
    if position == 0:
        for sys in [S1, S2]:
            if close[t] > DonchianHigh_EntryPeriod(sys)[t]:
                if sys == S1 and S1_LastTradeFilter and not last_trade_was_winner:
                    continue   # S1 过滤器：上一笔亏损则跳过
                开仓 1 unit
                last_trade_was_winner = true  # 重置过滤器
                break (S1 优先于 S2)

    # ---- 加仓信号 ----
    if 0 < position < MaxUnits:
        next_add_price = units[-1].entry_price + AddUnitATR × ATR[t]
        if close[t] >= next_add_price:
            加仓 1 unit

    # ---- 记录当日权益 ----
    equity_curve[t] = cash + position × close[t] × 每单位股数

返回 metrics, trades, equity_curve
```

### 3.2 仓位计算

采用 ATR 波动率标准化仓位管理（海龟法则核心：用 volatility 归一化不同标的的风险）:

```
每单位股数 = floor(账户总资金的 RiskPerUnit% / (StopATR × ATR(入场日)))
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| InitialCapital | 1,000,000 | 初始资金 (元) |
| RiskPerUnit | 0.01 (1%) | 每单位承担的风险占总资金比例 |
| MinShares | 100 | A 股最小交易单位 (1手=100股) |

**示例:** 初始资金 100 万，风险 1%，ATR(20)=2.5 元，StopATR=2.0
→ 每单位风险金额 = 10000 元
→ 每股风险 = 2.0 × 2.5 = 5.0 元
→ 股数 = 10000 / 5.0 = 2000 股 = 20 手

**简化处理（首版）:**
- 忽略滑点和交易成本（可配置开关）
- 仓位向下取整到整手（100 股整数倍）
- 不考虑资金不足导致加仓失败的情况（默认资金充足）
- 不考虑涨跌停无法成交的情况（首版简化）

## 6. 回测指标定义

### 6.1 核心指标 (P0)

| 指标 | 公式 | 说明 |
|------|------|------|
| 总收益率 (Total Return) | `(最终权益 - 初始资金) / 初始资金 × 100%` | 整个回测期的累计收益率 |
| 年化收益率 (Annual Return) | `(1 + Total_Return)^(252/N_days) - 1` | 折算为年化 |
| 最大回撤 (Max Drawdown) | `max(1 - 当前权益 / 之前最高权益) × 100%` | 历史最大亏损幅度 |
| 夏普比率 (Sharpe Ratio) | `(年化收益 - 无风险利率) / 年化波动率` | 风险调整后收益，无风险利率默认 2.5% |
| 胜率 (Win Rate) | `盈利交易笔数 / 总交易笔数 × 100%` | 盈利比例 |
| 盈亏比 (Profit Factor) | `总盈利 / 总亏损` | 盈利总额 / 亏损总额 |
| 交易次数 (Total Trades) | — | 所有开平仓对的次数 |
| 平均持仓天数 (Avg Hold Days) | `sum(每笔持仓天数) / 交易次数` | 平均持仓周期 |

### 6.2 扩展指标 (P1)

| 指标 | 公式 | 说明 |
|------|------|------|
| 卡尔玛比率 (Calmar Ratio) | `年化收益率 / 最大回撤` | 回撤效率比 |
| 年化波动率 | `每日收益率标准差 × sqrt(252)` | 波动风险度量 |
| 最大连胜/连亏 | — | 连续盈利/亏损笔数 |
| 平均盈利 / 平均亏损 | — | 单笔平均盈亏金额 |
| 最长回撤恢复天数 | — | 从最大回撤谷底回到前高需要多少天 |

### 6.3 交易明细表字段

| 字段 | 说明 |
|------|------|
| 系统 | S1 / S2 |
| 入场日期 | YYYY-MM-DD |
| 出场日期 | YYYY-MM-DD |
| 入场价 | 元 |
| 出场价 | 元 |
| 收益率 | % |
| 持仓天数 | 交易日 |
| 出场原因 | 止损 / 通道出场 |
| 加仓次数 | 该笔交易内的加仓单位数 |

## 8. 数据管理

### 8.1 输入数据契约 (与 task01 完全一致)

**数据源:**
- CSV 路径: `data/processed/{ts_code}_daily_{start}_{end}.csv`
- 编码: utf-8-sig
- 分隔符: 逗号
- Tushare MCP / REST API 拉取新数据

**必需字段:**
| 字段 | 类型 | 用途 |
|------|------|------|
| trade_date | str(YYYYMMDD) | 日期索引 |
| open | float | 开仓/跳空止损判断 |
| high | float | Donchian 通道上轨 |
| low | float | Donchian 通道下轨 + 止损触发 |
| close | float | 收盘判断、权益计算 |
| vol | float | 可扩展（流动性过滤） |

### 8.2 数据加载要求
- `trade_date` 转为 Date 对象，按升序排列
- 值列强制 float64/Number
- 校验: 行数 ≥ max(EntryPeriod_S2, ATR_Period) + 1（至少能覆盖 warmup 期），非负闭合价格
- 加载后过滤用户选择的日期范围 `[start_date, end_date]`

### 8.3 每日数据更新 (F19)

这是本看板区别于 task02 独立工具的关键功能。

**更新流程:**
```
1. 读取现有 CSV 的最大 trade_date → last_date
2. 如果 last_date >= 当前系统日期 → 提示"已是最新"，跳过
3. start_date = last_date + 1 交易日 (用 trade_cal 校验)
4. end_date = 当前日期
5. 按 stock_data_spec.md §7 增量更新流程:
   a. MCP tushareMcp → daily(ts_code, start_date, end_date)
   b. 如果 MCP 不可用 → 降级到 Tushare REST API
   c. 如果 REST API 也失败 → 新浪财经 API (P1)
   d. 如果全部失败 → 提示用户，使用现有数据
6. 增量数据与历史拼接，按 trade_date 去重保留最新
7. 更新 metadata JSON (fetch_time, update_history)
8. 覆盖写入 processed CSV
9. 自动触发回测重跑
```

**UI 交互:**
- "更新数据" 按钮位于顶栏，点击后显示进度（拉取中 → 校验中 → 合并中 → 完成）
- 拉取完成后显示简短 toast: "已更新 N 条数据，最新日期: YYYY-MM-DD"
- 如果已是当日最新数据，按钮变灰 + 提示"数据已是最新"
- 数据更新时间戳显示在页面底部

**降级与容错:**
- MCP 超时/不可用 → 自动尝试 REST API（参考 stock_data_spec.md §3 数据源优先级）
- 限频 (Tushare 40203) → 提示用户稍后重试，不阻塞
- 网络错误 → 保留现有数据，提示"更新失败，使用缓存数据"
- 更新过程中回测不中断（使用旧数据），更新完成后自动重跑

### 11.2 关键边界条件处理

| 场景 | 处理方式 |
|------|---------|
| warmup 期数据不足 | 不产生信号，权益曲线从 warmup_end 开始 |
| 首次入场后立刻止损 | 正常记录止损交易，last_trade_was_winner = false |
| 止损和通道出场同日触发 | 先止损（盘中），再通道出场（收盘）；已止损的单位不再被通道出场重复记录 |
| 加仓后当日即止损 | 每个单位的止损独立判断 |
| 多单位同时止损 | 依次处理每个单位，当日最低价判断 |
| 资金不足无法加仓 | 跳过一次加仓，继续持有现有单位（首版简化：默认资金充足） |
| 数据缺失日 | 跳过该日，不产生信号，权益不变 |
| 除权除息日 | 使用前复权数据，价格已自动调整 |
| 用户选择的日期范围 < warmup 长度 | 提示"数据不足，至少需要 N 个交易日"，不运行回测 |

### 11.3 性能目标

| 指标 | 目标 |
|------|------|
| 单标的回测耗时 | < 50ms (250 行数据) |
| 参数调节后 UI 重绘延迟 | < 150ms (含防抖 100ms + 重算 + 重绘) |
| CSV 加载 + 解析 | < 300ms |
| 内存占用 | < 50MB |
| K 线图渲染 (含 500 个标注) | < 200ms |

### 12.1 更新入口

```
[按钮] → 显示 progress modal →
```
